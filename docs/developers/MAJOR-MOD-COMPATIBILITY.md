# Major-mod compatibility baseline — 12 October 2026

This inventory comes from the user's four installed-mod screenshots. Versions were not visible. It is a compatibility target, not a certification that every combination or every feature works. Keep all entries, including part and utility mods; do not discard them as irrelevant. The startup correction is described in [issue 6](ISSUE-6-STARTUP-AUDIT.md).

## Strategy and boundaries

Ringworld supplies local vessel air, pressure, temperature, surface velocity, immersion and gravity through stock cache boundaries and the public `RingworldSurfaceApi` (v6) / `RingworldResourceApi` (v1). Orbital reference bodies remain real bodies. Globally changing the Sun's atmosphere, ocean or mass would break other craft and planetary systems. ModuleManager handles configuration; Harmony composes runtime consumers. Neither automatically converts spherical PQS coordinates, orbit predictions, background simulation or arbitrary body reads to a rotating cylindrical surface.

Patches now install once per class, with a separate owner, rollback on failure and a visible warning. Essential failures block new ring flight and pause a loaded resident without capturing an invalid replacement pose. Optional intake/resource failures leave rendering and controls available. `KSP.log` records competing owners of the harvester, intake, buoyancy and vessel-precalculation methods. Unknown failures must be investigated rather than hidden.

Normal installations leave `stockHarvesters` and `stockModuleEnvironment` enabled in `RINGWORLD_COMPATIBILITY`. Both are restart-required emergency switches, not a recommended workaround for KSPCF. Disabling them explicitly disables those local module adaptations.

## Source findings beyond the startup fix

[KSPCF ResourceConverterPerf 1.41.1](https://github.com/KSPModdingLibs/KSPCommunityFixes/blob/1.41.1/KSPCommunityFixes/Performance/ResourceConverterPerf.cs) caches by vessel/type/resource per rendered frame; ring/biome is absent. The scoped helper prefix bypasses that cache only for ring harvesting. [OnDemandPartBuoyancy](https://github.com/KSPModdingLibs/KSPCommunityFixes/blob/1.41.1/KSPCommunityFixes/Performance/OnDemandPartBuoyancy.cs) exits on a false host ocean flag. Ringworld's replacement now has first priority and retains that optimization for non-ring vessels. [FlightIntegratorPerf](https://github.com/KSPModdingLibs/KSPCommunityFixes/blob/1.41.1/KSPCommunityFixes/Performance/FlightIntegratorPerf.cs) replaces several methods; the successful runtime is stronger evidence than merely finding compatible-looking source.

[BRP's harvester](https://github.com/Phantomical/BackgroundResourceProcessing/blob/main/src/BackgroundResourceProcessing/Converter/BackgroundResourceHarvester.cs) bypasses PrepareRecipe in one path, so the loaded stock drill scope does not cover it. [BRP intake behavior](https://github.com/Phantomical/BackgroundResourceProcessing/blob/main/src/BackgroundResourceProcessing/Converter/BackgroundResourceIntake.cs) also reads the real host's oxygen/ocean. The mod provides its own [integration framework](https://github.com/Phantomical/BackgroundResourceProcessing/wiki). This requires an explicit background integration, not a claim that Harmony makes every module automatically compatible.

[BackgroundThrust](https://github.com/Phantomical/BackgroundThrust) advertises loaded/packed/unfocused burns with BRP or Kerbalism. Ring residences must remain stationary when landed, and leave that state when thrust genuinely initiates departure. [Relativity](https://github.com/Vannadin/Relativity) has thrust, clock and visual behavior tied to inertial travel, including its own BRP/BackgroundThrust adapters. Neither has been runtime certified on a ring by this audit.
